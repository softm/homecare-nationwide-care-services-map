## 실행

Node.js 24와 Playwright, 해당 버전의 Chromium이 필요하다. Playwright가 현재 프로젝트의 모듈 경로에 없으면 `PLAYWRIGHT_MODULE`에 설치된 `playwright` 패키지 경로를 지정한다.

```sh
AUDIT_MODE=checkout node scripts/check-ui-playwright.mjs
AUDIT_MODE=live AUDIT_FILTER='signup|login|map-(saved|compare|filter)' node scripts/check-ui-playwright.mjs
```

| 설정 | 기본값과 의미 |
| --- | --- |
| `AUDIT_MODE` | `checkout`: 운영 Origin에서 로컬 정적 파일을 응답. `live`: 배포된 정적 파일 사용 |
| `AUDIT_WIDTHS` | `320,390,768,1024,1440` |
| `AUDIT_FILTER` | 화면 상태 이름에 적용할 정규식. 생략 시 전체 |
| `AUDIT_OUTPUT` | 보고서와 스크린샷을 남길 폴더. 생략 시 시스템 임시 폴더 |
| `AUDIT_LABEL` | 결과 하위 폴더. 생략 시 실행 모드 이름 |
| `AUDIT_SCREENSHOTS` | `all`이면 모든 크기에서 촬영. 기본은 390·1440px 및 실패한 검사 |

`report.json`에 화면 상태·폭·HTTP 상태·가로 넘침·선택 입력 크기·메뉴 겹침·가려진 주요 버튼·깨진 이미지·스크립트 오류를 기록한다. 실패가 있으면 종료 코드 1을 반환한다.

## 운영 자료 보호와 해석

로그인 이후 화면의 회원·신청·사진·상담 정보는 명백한 가상 응답이다. API Origin 요청을 가로채며, 그 밖의 POST·PUT·PATCH·DELETE는 차단한다. 실제 회원을 만들거나 문서를 제출·심사·삭제하지 않고, 브라우저 저장소도 시험별 독립 컨텍스트에서만 사용한다. 비밀번호·세션 쿠키·실제 토큰·사업자등록증은 검사 결과에 포함하지 않는다.

`live`도 같은 원칙을 적용한다. 이는 **운영 배포 자산의 UI 검사**이며 실제 로그인·업로드 API의 통합 검사와 구분한다. 실제 API 검증 기록은 `HOMECARE-DEPLOYMENT.md`에 있다. headless Chromium 결과를 실제 iOS·Android 기기 검사로 간주하지 않는다.
