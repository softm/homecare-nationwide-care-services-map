`scripts/check-ui-playwright.mjs`는 별도 headless Chromium을 실행한다. 사용자가 쓰는 Chrome과 Aside의 로그인 탭은 건드리지 않는다.

## 실행

Node.js 24와 Playwright, 해당 버전의 Chromium이 필요하다. Playwright가 현재 프로젝트의 모듈 경로에 없으면 `PLAYWRIGHT_MODULE`에 설치된 `playwright` 패키지 경로를 지정한다.

```sh
AUDIT_MODE=checkout node scripts/check-ui-playwright.mjs
AUDIT_MODE=live AUDIT_FILTER='signup|login|map-(saved|compare|filter)' node scripts/check-ui-playwright.mjs
```

| 설정 | 기본값과 의미 |
| --- | --- |
| `AUDIT_MODE` | `checkout`: 운영 Origin에서 로컬 정적 파일을 응답. `live`: 배포된 정적 파일 사용 |
| `AUDIT_WIDTHS` | `320,390,768,1024,1440` |
| `AUDIT_FILTER` | 화면 상태 이름에 적용할 정규식. 생략 시 전체 |
| `AUDIT_OUTPUT` | 보고서와 스크린샷을 남길 폴더. 생략 시 시스템 임시 폴더 |
| `AUDIT_LABEL` | 결과 하위 폴더. 생략 시 실행 모드 이름 |
| `AUDIT_SCREENSHOTS` | `all`이면 모든 크기에서 촬영. 기본은 390·1440px 및 실패한 검사 |

`report.json`에 화면 상태·폭·HTTP 상태·가로 넘침·선택 입력 크기·메뉴 겹침·가려진 주요 버튼·깨진 이미지·스크립트 오류를 기록한다. 실패가 있으면 종료 코드 1을 반환한다.

## 검사 범위

- 일반·기관 가입, 로그인, 비밀번호 복구, 일반·기관 내 정보, SNS 추가정보 화면, 보관함·탈퇴 확인창
- 기관 등록 양식과 제출·승인·보완 상태, 운영자 심사, 기관 협약·정보·사진·조회 현황
- 담은 기관, 시설 비교·상세, 상담 기록·질문·가족 공유
- 맞춤 조건 입력 → 후보 조회 → 두 기관 담기 → 비교 → 상담 준비
- 지도·목록·전체지도, 햄버거 메뉴, 유형 선택, 상세필터·상세조건, 맞춤조건 3단계, 담은 기관·비교창·시설 상세
- 서비스 안내·소개·비용·사진·자료 현황·약관·개인정보·유형별 안내, 이전 지도 경로
- 지역 페이지는 시도·시군구 템플릿을 각각 확인한다. 815개 생성 지역 페이지의 경로·원본 정합성은 별도 `npm run check`가 검사한다.

가입 유형은 실제 카드 클릭과 방향키로 전환한다. 상세조건 체크박스와 지도 비교 버튼도 실제 클릭한다. 비교표 내부의 의도된 가로 스크롤은 페이지 전체 가로 넘침과 구분한다.

## 운영 자료 보호와 해석

로그인 이후 화면의 회원·신청·사진·상담 정보는 명백한 가상 응답이다. API Origin 요청을 가로채며, 그 밖의 POST·PUT·PATCH·DELETE는 차단한다. 실제 회원을 만들거나 문서를 제출·심사·삭제하지 않고, 브라우저 저장소도 시험별 독립 컨텍스트에서만 사용한다. 비밀번호·세션 쿠키·실제 토큰·사업자등록증은 검사 결과에 포함하지 않는다.

`live`도 같은 원칙을 적용한다. 이는 **운영 배포 자산의 UI 검사**이며 실제 로그인·업로드 API의 통합 검사와 구분한다. 실제 API 검증 기록은 `HOMECARE-DEPLOYMENT.md`에 있다. headless Chromium 결과를 실제 iOS·Android 기기 검사로 간주하지 않는다.

## 2026-11-21 수정

1. 텍스트 입력 스타일이 라디오까지 확장되던 원인을 제거하고 일반·기관 유형을 클릭 가능한 선택 카드로 정리했다.
2. 지도 상세조건 체크박스에도 적용되던 입력 최소 높이 규칙을 분리했다.
3. 모바일 담은 기관의 비교·경로 버튼을 공용 하단 메뉴 위에 배치하고 실제 클릭으로 확인한다.
4. 상세필터·담은 기관·기관 상세에서 로그인 버튼이 내용과 닫기 버튼을 덮지 않도록 했다. 회원·기관·상담 화면의 설치 버튼은 문서 끝에 둔다.
5. 닫힌 유형 메뉴의 컨테이너를 실제 버튼 폭으로 제한하고 설치 안내의 서비스 이름을 명시했다.
6. 변경된 CSS·가입 모듈 URL과 오프라인 회원 셸 해시를 함께 갱신했다. 버전 쿼리를 무시해 예전 스타일을 반환하던 서비스워커도 수정했다. 새 버전·동일 버전·오프라인 복원·인증 캐시 제외를 회귀 검사한다.

검증 환경은 Playwright 1.64.1 / headless Chromium 156.0.8078.4이다. 36개 경로에서 76개 화면 상태를 5개 폭으로 검사한 **380개 조합이 통과**했다. 기관 상세는 이동 애니메이션 완료를 기다린 뒤 5개 폭에서 별도 재검사했으며 닫기 버튼을 가리던 문제의 수정도 확인했다. 390·1440px의 전체 페이지 이미지와 추가 상세창 이미지를 시각 검토했다.

외부 통신을 차단한 로컬 HTTP 서버에서도 실제 Chromium 서비스워커를 등록해, 이전 스타일을 넣은 캐시에서 새 버전 파일을 받아오는 동작과 오프라인 셸 복원을 확인했다.

`npm run check`는 새 캐시 회귀 검사 4개를 포함해 **637개**, 회원 화면 셸 **280개**, 기존 Python·정적 자료·지역 페이지 검사까지 통과했다. 브라우저 검사와 동시에 실행한 중간 검사에서 기존 좌표 처리의 시간 제한 검사가 한 번 실패해, 브라우저 종료 후 전체 검사를 단독 재실행해 통과를 확인했다. 해당 지도 로직이나 시간 제한은 변경하지 않았다.

## 2026-11-21 맞춤 후보 목록 가독성·비교 개선

<!-- SOFTM-CANDIDATE-FACTS START 날짜:20261121 : 지도 목록과 같은 공개자료를 큰 지표로 비교하고 실제 담기·상담 동선까지 확인 -->

- 후보 카드의 기관명은 PC 24px·모바일 22px, 거리·평가·정원·인력 수치는 25~27px로 표시한다. 미확인은 숫자 0으로 대체하지 않는다. 모바일은 2열이며 홀수 개 지표의 마지막 칸은 전체 폭을 사용한다.
- `CareDecisionSummary.summary`의 기존 유형별 판정을 재사용한다. 방문간호는 간호인력, 요양병원은 기관 구분·개설일을 표시한다. 혼합 서비스인 치매전담형은 정원이 적용되지 않는 자료에 `유형별 확인`을 표시해 지표 위치를 유지한다.
- 요양원·주야간보호·방문요양의 비용은 지도 목록과 동일한 `CareCostPreview`로 계산한다. 공통 조건 예시·적용연도·비급여 제외를 함께 표시한다. 다른 유형에 임의의 금액을 표시하지 않는다.
- 선택 조건의 확인·다름·확인 필요 상태를 각각 표시하고, 상담 질문 전체를 접고 펼칠 수 있다. 담기·해제는 버튼과 카드 테두리에 동시에 반영된다. 기관 상세·사진·비교·상담 이동을 유지한다.

독립 headless Playwright에서 9개 유형의 후보, 조건을 선택한 후보, 비교, 상담, 지도 목록·상세의 14개 상태를 320·390·768·1024·1440px에서 검사해 70개 조합을 통과했다. 유형별 실제 수집 자료의 값과 공용 목록 지표·비용이 일치하는지, 계산된 글자 크기, 질문 펼침·접기, 담기·해제와 카드 표시, 비교·상담 이동을 확인했다. 단기보호 카드는 공개 기관이 있는 광진구 위치에서 검사한다. 카드 단독 스크린샷에서는 고정 메뉴만 일시적으로 숨기고, 전체 화면과 실제 클릭 검사는 메뉴를 유지한다.

```sh
AUDIT_FILTER='^(analysis-candidates.*|analysis-compare|analysis-prepare|map-list|map-detail)$' AUDIT_MODE=checkout node scripts/check-ui-playwright.mjs
```

마지막 모바일 줄바꿈·단일 상세 버튼 폭 보정은 320·390px에서 6개 조합을 별도로 재검사했다. 전체 `npm run check`의 638개 검사, 285개 셸 자산과 Python·정적 자료 검사도 통과했다.

회원 API 가상 응답과 쓰기 요청 차단 원칙을 유지한다. 이번 검증은 기관 회원의 실제 로그인·업로드 검사를 다시 수행한 것이 아니다.

## 2026-11-21 추가 조건 미선택 확인

<!-- SOFTM-EMPTY-CONDITIONS START 날짜:20261121 : 원치 않는 조건 없는 검색을 실행하기 전에 선택 의사를 확인 -->

추가 조건을 선택할 수 있는 유형에서 적용 조건이 0개이면 `추천 후보 보기` 클릭과 주소 입력창의 Enter 모두 `추가 조건 없이 찾을까요?` 확인창을 연다. `그냥 찾기`는 기존 유형·위치·거리로 검색하고, `조건 선택하기`와 Esc는 검색하지 않고 조건 영역을 펼쳐 첫 체크박스로 초점을 돌려준다. 주소와 기존 입력은 유지하며, 확인창을 다시 열 때 이전 진행 응답을 재사용하지 않는다. 이미 적용한 조건이 있거나 추가 조건 자체가 없는 요양병원은 바로 검색한다.

Playwright에서 확인창, 조건 없는 검색 진행, 선택 조건 검색, 요양병원 검색, 비교, 상담의 6개 상태를 320·390·768·1024·1440px로 검사해 30개 조합을 통과했다. 네이티브 dialog의 닫힘 이벤트 후 초점 복귀 완료를 기다려 Esc·취소·재진입·Enter를 검사한다. 별도 숨김 브라우저와 가상 회원 응답·쓰기 차단 원칙을 유지한다.
