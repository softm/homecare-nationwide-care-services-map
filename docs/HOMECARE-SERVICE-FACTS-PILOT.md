작성: 2026-11-21. 기존 정적 HTML/JS, 전국 9개 유형 지도·맞춤찾기, 전용 회원 Worker와 기관 D1을 유지한다. 이 문서는 구현된 기능과 앞으로 실제 협력 기관·보호자와 수행할 운영 계획을 구분한다. 아래 숫자는 목표이며 실적이 아니다.

## 보호자에게 제공하는 차이

| 단계 | 기존 공공자료 검색 | 이번에 추가한 기능 |
|---|---|---|
| 후보 찾기 | 거리·공단 평가·등록 인력·정원 | 참여 기관이 최근 확인한 요일·자리·송영·비급여·지원 조건 |
| 출처 판단 | 공공자료 기준일 | 항목별 담당자 확인/운영자 통화 확인, 확인일·다음 확인일 |
| 비용 비교 | 공식 수가와 직접 입력한 비급여 | 같은 등급·본인부담 유형·이용 일수에 최근 확인한 일/월 비급여 적용 |
| 실제 이용 확인 | 전화번호와 일반 질문 | 희망 요일·시간·지원 조건을 보존한 통화 결과 기록 |
| 가족 공유 | 선택한 질문·답변·메모 | 명시적으로 선택한 통화 결과만 추가 공유, 개인 조건은 제외 |

다른 민간 서비스에 위 기능이 없다고 주장하는 경쟁사 비교가 아니다. 공공자료에 기반한 검색 기능만으로 현재 자리를 확정할 수 없다는 한계를 보완하는 내부 기능 정의이다. 확인 배지·참여 여부·유료 상품은 기관 품질 점수나 검색 우선순위를 바꾸지 않는다.

## 적용 경계

- 기관회원 가입·사업자등록증 심사와 승인된 owner/editor 권한을 사용한다.
- 기관 담당자가 기존 무료 시범운영·콘텐츠 공개 동의를 완료한 공단 주야간보호 기관만 운영자가 참여로 설정한다. 실제 동의 없는 기관을 자동 등록하지 않는다.
- 관리: `institution-portal.html`의 **이번 주 이용정보** 탭.
- 운영자: `care-pilot-admin.html`. `institution-review.html`에서 진입한다. 쓰기는 기존 10분 이내 재인증 정책을 따른다.
- 보호자 안내: `care-pilot.html`. 기관/복지기관/커뮤니티별 `src` 링크와 인쇄용 QR 제공. 기관 미모집 상태는 준비 중으로 표시한다.
- 지도 목록·상세 팝업, 맞춤 후보, 담은 기관, 단독 상세, 비교표에 동일 모듈을 사용한다. 최근 확인 필터는 참여 기관의 5항목 기준이며 기존 거리 정렬을 유지한다.
- 비참여 기관·공개 API 장애에도 기존 전국 공개자료 검색은 유지한다.
- 실제 기관 모집, 보호자 모집, 유료 계약, 운영 서비스 배포는 코드 작성만으로 완료되지 않는다.

## 정보 규칙

1. `schedule`: 선택한 요일별 시작/종료. 빈 요일 배열은 미확인.
2. `availability`: 요일별 상담 가능/대기 접수/이용 불가/미확인. 인원 `0`과 `null`을 구분한다. 정원·등록 현원으로 빈자리를 추정하지 않는다.
3. `shuttle`: 지역과 픽업 조건. 지역에 포함되어도 자택 픽업이나 휠체어 탑승 확정은 아니다.
4. `fees`: 식비/일, 간식비/일, 기타 비급여/월. `null`은 미확인, 0은 비용 없음. 조건별 비용을 모두 포함했다고 명시하고 세 금액을 모두 확인한 경우에만 합산한다. 선택형·횟수형 추가 비용이 있으면 전체 포함을 선택하지 않는다.
5. `support`: 담당자에게 실제 확인한 지원 범위와 제한. 자격·공단 특화·인력 수를 실제 대응 가능 판정으로 대체하지 않는다.

항목마다 `draft`, `live`, `revision`을 분리한다. 초안 저장은 공개 상태·확인일을 바꾸지 않는다. 저장된 항목 중 사용자가 명시적으로 선택한 항목만 확인 게시한다. 변경 없음도 같은 선택 확인 동작을 사용한다. 공개 시 서버 시각으로 확인일을 기록하고 정확히 7일 후 만료한다. 만료한 값은 참고자료로 남고 **재확인 필요**가 되며, 최근 정보 필터와 비급여 자동 합산에서 제외한다. `source`는 클라이언트 입력을 신뢰하지 않고 권한에 따라 서버가 지정한다.

동시 수정은 항목 revision 검증과 D1 원자적 batch로 처리한다. 충돌하면 모든 변경·감사 기록을 함께 취소한다. 담당자가 소개글·사진을 수정해도 항목 확인일을 갱신하지 않는다. 참여 중단·기관 중지·동의 철회·승인된 관리 권한 회수 시 신규 공개 조회에서 제외한다.

## 상담과 개인 정보

- 별도 문의/채팅 전달 시스템을 만들지 않는다. 공식 공개 연락처 또는 기관 공개 연락처로 전화하고 보호자가 결과를 기록한다.
- 결과: 가능하다고 안내받음 / 조건부 가능 / 어려움 / 확인 못함.
- 기록 당시 희망 요일·시간·지원 조건, 실제 확인 날짜를 보존한다. 현재 상담 조건을 바꾸면 **이전 조건으로 확인한 결과**를 표시한다.
- 기존 상담 질문·메모·방문 일정·계정 저장/복원을 유지한다. 방문 완료는 별도 명시적 선택이며, 기존 ‘확인 완료’ 상태나 전화 버튼 클릭으로 추정하지 않는다.
- 신규 기록도 기존 사용자 workspace에 저장하므로 소유권·revision·보관소/계정 삭제 정책을 그대로 적용한다.
- 공유의 `includeUseCheck` 기본값은 false. 포함을 선택해도 확인일·항목별 결과·방문 상태만 전달한다. 희망 조건의 자유문구, 환자 정보, 보호자 연락처는 자동 공유하지 않는다.
- 기관 공개정보/감사 근거에는 개별 환자 이름·전화번호를 입력하지 않도록 안내한다.

## 수가·예상 비용

수가표와 기존 CareCostEngine은 그대로 사용한다. 수가 연도·확인일·공식 출처와 급여 적격성·특례 안내를 유지한다. 등급만으로 확정 비용을 산출하지 않는다.

`급여 본인부담 + 한도 초과 전액 부담 + (식비/일 + 간식비/일) × 이용 일수 + 기타 비급여/월`

신선도·금액·전체 포함 여부를 충족하고 별도 적용 조건이 없는 기관 확인액만 자동 사용한다. 자유문구 적용 조건이 있으면 충족 여부를 자동 추정하지 않고 직접 확인한 월 금액을 입력하도록 안내한다. 보호자가 직접 확인한 월 비급여를 입력하면 그 수동 입력을 우선한다. 미확인/만료/일부 누락 시 **급여 기준 약 …**과 비급여 미포함을 명시한다. 이용 시간·일수·본인부담 유형 변경 시 다시 계산한다. 요양병원·특례 등 기존 엔진 비지원 조건에 일반 수가를 적용하지 않는다.

## API와 DB

- 기관 D1 migration: `services/cloudflare-homecare/migrations/0007_service_facts.sql`.
- 테이블: `service_pilot`, `service_facts`, `service_fact_audit`, `service_pilot_events`.
- `GET /api/public/service-facts?ids=...`: 최대 50개 공단 기관기호. 미지정 시 활성 참여기관 최대 50곳. 공개 스냅샷만 반환. 일괄 조회를 합쳐 화면별 개별 요청 폭증을 방지한다.
- 회원 Worker는 게이트웨이로 들어온 공개 기관·사진·집계 경로를 기관 Worker로 전달한다. 공개 전달에는 Cookie·Authorization·CSRF 헤더를 제거한다.
- 기존 `GET /api/public/institutions/:id`에는 `serviceFacts`를 추가하고 기존 필드를 보존한다. 추가 조회 실패는 기존 소개 응답을 막지 않는다.
- `GET/PUT /api/institutions/:id/service-facts`: 승인된 담당자; PUT은 CSRF 필수. `action=draft|confirm`, `items=[{key,revision,value,conditions}]`. confirm에는 key/revision만 사용한다.
- `GET/PUT /api/admin/institutions/:id/service-facts`: 운영자, 확인 근거·지원 시간 필수.
- `PUT /api/admin/institutions/:id/service-pilot`: 참여 설정/중단, revision·사유 필수.
- `GET /api/admin/service-pilot`: 참여/확인 현황, 주간 지원 시간, 유입별 행동 집계.
- `POST /api/public/pilot-events`: visit/save/compare/phone/consultation/visit_scheduled/visit_completed. 허용 Origin과 등록된 참여 기관만 수락, 기관 없는 landing은 visit만 허용.
- 공개 조회와 개인 응답은 no-store. PWA에는 정적 코드·스타일·QR만 포함하고 API·개인기록·최신 운영정보는 선캐시하지 않는다.

## 실제 4주 운영

| 기간 | 수행 | 산출·판정 |
|---|---|---|
| 1주 | 협력 가능한 기관 10곳 접촉, 보호자 10명 인터뷰, 담당자와 확인 주기 협의 | 실제 동의한 주야간보호 3~5곳. 특정 지역은 협력기관이 정해진 후 선택 |
| 2주 | 기관 가입·승인·참여 설정, 5항목 입력·초기 확인, 링크·QR 안내 시작 | 기관별 확인일·담당 부서·운영 보조 시간. 320~1440px 사용자 흐름 점검 |
| 3~4주 | 최소 주 1회 갱신 점검을 2회 연속 수행, 보호자 20명 이용 관찰 | 상담 기록 6명 이상, 방문 예정/완료 3명 이상, 주간 최신 갱신율 80% 이상 2회 연속 |
| 4주 말 | 재확인 부담·이용 결과 인터뷰, 비용/가치 검토 | 5기관 기준 운영 지원 주 120분 이하, 차별성/유료 의사 결정 |

### 구체적인 유입 방법

- **기관 담당자 안내 5명 목표**: 이미 전화 문의한 보호자에게, 상담 전에 비용·송영 질문을 준비하는 링크 또는 인쇄 QR 안내. 담당자의 안내 동의를 먼저 받는다. 기관별 직접 연락을 대신 보내지 않는다.
- **복지기관 안내 5명 목표**: 참여기관 생활권의 복지관·치매안심센터 등 실무자에게 ‘처음 주야간보호를 알아볼 때 확인할 5항목’ 한 장을 설명하고, 안내 가능 여부를 협의한 뒤 배포한다. 협약이나 추천을 확보한 것으로 표현하지 않는다.
- **지역 보호자 커뮤니티 10명 목표**: 운영자의 게시 허가를 받은 경우, 실제 확인할 수 있는 지역과 현재 등록된 기관 범위를 명시한 상담 질문 도구를 안내한다. 홍보 게시나 메시지 발송은 별도 실제 실행 승인이 필요하다.
- 유료 광고를 전제하지 않는다. 방문을 유도하는 이유는 ‘기관 검색’ 자체보다 실제 확인일이 있는 요일·송영·비용 정보와 전화 질문 준비이다.

링크: `/care-pilot.html?src=institution`, `?src=welfare`, `?src=community`. QR 파일은 각각 `assets/pilot/qr-*.png`. 인쇄 전 링크 공개 여부를 확인한다.

### 측정과 중단 기준

자동 집계는 **일·기관·행동별 브라우저 중복 제거 합계**다. 날짜·기관 간 같은 보호자를 중복 집계할 수 있으므로 20명/6명/3명 판정이나 단순 나눗셈 전환율에 사용하지 않는다. 별도의 참여 동의를 받은 운영대장에서 임의 참여자 코드로 실제 보호자 수를 확인한다. 상담 내용·환자 정보는 집계 API로 보내지 않는다. 일별 식별값은 기존 서버 비밀값으로 해시하며 90일 후 삭제한다. 집계 테이블은 일 5,000건 상한을 두되 모든 인프라 과금이 절대 차단된다고 보장하는 장치는 아니다.

기관 3곳 미만, 2회 연속 갱신율 80% 미만, 실제 상담으로 이어지는 가치 부족, 운영 지원 시간이 지속적으로 주 2시간을 초과하면 범위 확대를 보류하고 질문·입력 부담부터 줄인다. 참여가 중단되면 공개 정보에서 제외한다.

무료 시범운영에 결제 기능은 없다. 결과 확인 후 기존 기관 소개페이지 운영 상품의 유료 수요 인터뷰를 별도로 진행한다. **5기관 중 1기관 유료 계약 의향/전환**은 후속 가설이며 확정 실적이 아니다. 확인 배지·검색 순위와 결제를 연결하지 않는다. 실제 계약 전에 가격·제공 범위·계약기간을 확정한다.

## 배포와 되돌리기

1. 새 배포 전 기관 D1의 보호된 백업과 현재 Worker 버전을 확보한다. 자격증명은 출력/커밋하지 않는다.
2. 승인된 배포에서 기관 D1 migration 0007을 적용한다. 기존 데이터를 수정·삭제하지 않는 추가 migration이다.
3. 기관 Worker → 회원 Worker → 정적 자산/셸 순서로 배포한다. 새 public/private 경로가 기존 API 도메인 라우팅을 통과하는지 확인한다.
4. 실제 동의를 받은 기관만 운영자 화면에서 참여를 설정한다. 비회원 공개 조회, 담당자 수정, 운영자 재인증, 개인 기록 저장, 공유 제외를 운영 환경에서 최종 점검한다.
5. 장애 시 기관 참여를 중단하거나 이전 프런트/Worker 버전으로 되돌린다. 신규 테이블을 삭제하지 않는다. 기존 전국 검색·회원 자료는 유지한다.

현재 변경의 로컬 검증 결과와 운영 배포 여부는 최종 작업 보고에 별도로 남긴다. 로컬 시험기관은 메모리 SQLite에만 존재하며 운영 기관 등록/회원 가입/메시지 전송을 수행하지 않는다.
