## 가입 정책

- 일반 아이디 가입: 아이디·비밀번호·필수 약관으로 즉시 완료. 이름·이메일·휴대폰은 필수 아님.
- 일반 SNS: 카카오·네이버·Google 제공자 식별자로 연결. 이름·휴대폰·시도·시군구·필수 약관 완료 전 서버 기록 사용을 제한한다. 휴대폰 본인인증은 이번 범위에 포함하지 않는다.
- 기관회원: 아이디·비밀번호 전용. 기관 유형·실제 기관 또는 수기 신청·주소·사업자등록번호·대표자·담당자 연락처/이메일·사업자등록증 제출이 필수. 제출 후 가입 완료, 승인 전 기관 관리 권한 없음.
- 복구코드는 발급 화면에서만 표시하고 해시만 저장한다. 비밀번호 재설정 시 이전 코드와 세션을 폐기한다. SNS 계정을 이메일 일치로 자동 합치지 않는다.

## 저장·삭제

기기 초안은 기존 `sessionStorage`를 사용한다. 새 계정으로 바뀌거나 로그아웃하면 이전 계정의 기기 자료를 지운다. 브라우저/탭을 닫기 전에 계정 저장을 선택해야 다른 기기에서 이어갈 수 있다. 서버 자료를 자동 덮어쓰지 않고 불러오기/합쳐 저장을 사용자가 선택한다. 동시 저장 충돌은 revision으로 거부한다.

내 보관소 삭제는 서버 작업공간·공유·돌봄 대상자/동의 기록·기관 신청 증빙과 기기 초안을 삭제한다. 계정과 승인된 기관 관리 권한은 유지한다. 탈퇴는 계정과 SNS 식별자·세션을 삭제하고 기관 멤버십을 해제한다. 파일 저장소 삭제 실패는 재시도 작업으로 남기며 성공으로 표시하지 않는다. 공식 기관 운영정보는 별도 관리 대상이다.

## 검증과 배포 구분

- API 자동 검사: 실제 SQLite로 회원 격리, 복구 일회성, Origin/CSRF, SNS 추가정보, 공유 범위·만료, 기관 증빙·심사·승인 충돌, 삭제 실패 재시도를 검사한다.
- 실제 로컬 Wrangler: 회원 D1 + 기관 D1 + 비공개 R2 + 양방향 서비스 바인딩으로 일반 가입, 기관 검색·증빙 제출, 운영자 승인, 기존 기관 관리 협약과 탭을 검증한다. 검증 데이터는 로컬에만 존재한다.
- 브라우저: 실제 공개 기관을 시험 후보로 사용해 3곳 비교 제한, 질문·답변 보존, 계정 저장, 별도 비로그인 브라우저의 공유 열람을 검증한다. 로컬 주소는 기존 Naver 지도 허용 Origin이 아니므로 지도 타일·주소 API 오류를 운영 장애로 단정하지 않는다.
- Android: 공통 키로 서명한 Release를 별도 에뮬레이터에 설치해 확인한다. 현재 운영 웹에는 신규 회원 화면/API가 배포되지 않아 실계정 SNS 복귀·파일 제출 전체 과정은 배포 후 추가 검증해야 한다.

## Bunzee 기획과의 적용 기준

프로젝트 `9ab7c3a1-73d3-4cfb-8c8d-469fb47a1f4f`의 PRD·IA·와이어프레임·`grammarly` 스타일/프로토타입을 참고한다. Bunzee 개발환경은 미설정 기본값(TypeScript/Next.js/PostgreSQL)이었으며, 이후 사용자의 **현재 구조 유지** 지시를 우선했다. 참고 앱 키는 없었다.

IA의 18개 화면은 위 표의 기존/신규 화면에 통합했다. 소개는 기존 이용 안내, 조건·후보는 맞춤 찾기의 단계, 질문·방문 점검은 같은 상담 상세, 설정·프로필·알림·계정 삭제는 내 정보로 연결한다. 구독 관리는 승인된 범위에 따라 결제 없이 현재 무료 이용 상태를 표시한다. 이메일 가입/재설정은 사용자 지정 아이디 가입/일회용 복구코드 정책으로 바꿨다. 기획서의 가상 추천 점수·비용·기관명을 실제 운영 자료처럼 표시하지 않는다.

디자인 토큰: primary `#15C39A`, surface `#F7F8F8`, border `#E4E6E6`, text `#1A1A1A`, muted `#6B6B70`, 12px 입력/16px 카드/20px 대화상자/둥근 버튼. 한글은 기존 로컬 Pretendard를 유지한다. 지도 실사/기본 전환의 기존 파랑 계열과 레이어 아이콘은 기능 표준을 유지한다.

## 보호자와 돌봄 대상자

일반 회원 계정이 연락받을 보호자다. 아이디 가입은 기존처럼 즉시 완료하며, 내 정보에서 보호자 이름·휴대폰을 저장한 다음 대상자와의 관계(부모·배우자·자녀·형제자매·그 밖의 가족·본인·기타), 성별, 이동 상태와 필요한 돌봄을 등록한다. 현재 계정당 대상자 한 명을 관리하며 대상자 이름·전화번호·상세 진단서 원문은 받지 않는다.

`GET/PUT/DELETE /api/me/care-recipient`는 가입 완료한 일반회원만 접근한다. PUT/DELETE는 CSRF와 `If-Match`를 검증한다. 별도 동의 버전·시각과 입력 권한 확인은 `care_recipients`에 저장하고 연락처는 현재 계정에서만 읽는다. 기관회원·다른 계정으로 조회하거나 요청 본문으로 연락 대상을 바꿀 수 없다. DB 제약은 동시 요청에서도 연락처 없는 대상자가 남지 않게 한다.

상태정보는 일반 가입 약관과 분리해 동의를 받고, 대상자 본인 동의 또는 법정대리 권한을 확인한다. 설계 참고: [개인정보 보호법 제23조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029335227). 가족 관계를 법정대리 권한으로 간주하지 않는다.

맞춤 찾기에서 사용자가 **대상자 조건 적용**을 누르면 해당 유형의 공개자료로 확인 가능한 치매·인지 조건을 연결한다. 관계·성별·이동·재활·간호 상태만으로 순위를 정하거나 기관을 임의 제외하지 않는다. 자료가 부족한 항목은 일반 상담 질문으로 준비한다. 대상자에서 유도된 조건은 일반 검색 저장본에 자동 복사하지 않는다. 일반 질문은 사용자가 선택한 상담 기록 공유에 포함될 수 있지만 대상자 원문·보호자 연락처는 자동 포함하지 않는다.

상담 목록·상세·맞춤 상담 준비에는 가입한 보호자의 연락처를 표시한다. 문자·이메일 발송 서비스는 연결하지 않았으며 전송 완료를 표시하지 않는다. 연락처 입력은 본인인증을 의미하지 않는다. 대상자 삭제는 동의 기록도 삭제하고, 보관소 삭제·탈퇴에도 같은 삭제를 포함한다. 이미 별도로 작성한 상담 기록은 해당 화면에서 관리한다.

## 장기요양등급과 예상 비용

일반회원 가입 완료(복구코드 보관 이후)와 SNS 추가정보 완료 이후에 선택 입력 화면 `care-account.html?view=care-setup`을 제공한다. 보호자 연락처와 대상자 등급·본인부담 유형을 등록하거나 건너뛸 수 있다. 기존 계정은 `care-account.html#careRecipient`에서 같은 항목을 관리한다.

대상자 API는 `grade`(빈값·1~5·cognitive)와 `burden`(빈값·general·reduced40·reduced60·exempt)을 검증해 기존 비공개 JSON에 저장한다. 별도 D1 스키마 변경은 없다. 서버도 루트 `care-recipient-model.mjs`를 번들하므로 이 모델 수정은 회원 Worker 배포가 필요하다. 기존 프로필의 누락 필드는 미확인으로 유지하고, 새 저장은 비용 계산 목적을 포함한 `care-recipient-20261121-cost` 동의를 기록한다. 소유권·CSRF·연락처·수정 버전·삭제·공유 제외 규칙은 그대로 적용한다.
