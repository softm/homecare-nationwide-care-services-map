# 케어닥 비교 기반 돌봄한눈 정보·UX/UI 방향

- 조사일: 2026-11-18
- 조사 범위: 케어닥 비로그인 공개 홈, 시설찾기, 시설 상세, 돌봄 서비스, 고객지원·FAQ
- 참고 URL: `https://www.caredoc.kr/`, `https://www.caredoc.kr/facility`, `https://www.caredoc.kr/services`, `https://www.caredoc.kr/support`, `https://www.caredoc.kr/support/faq`
- 원칙: 케어닥의 상표·문구·이미지·색상을 복제하지 않고 정보 구조와 의사결정 흐름만 비교한다.

## 1. 관찰한 경쟁 UX

케어닥 시설찾기는 데스크톱에서 왼쪽 필터와 가로형 결과 행을 사용한다. 한 행은 사진, 기관 기본정보·특징 태그, 월비용 예시·상세 CTA로 나뉜다. 상세에서는 사진 갤러리, 평가, 비용, 정원·이용 현황, 인력, 시설, 프로그램, 교통·주차 정보를 긴 탭형 문서로 제공한다.

장점은 사진과 문의 행동이 빠르고, 사용자가 익숙한 시설 중심 언어를 사용한다는 것이다. 반면 추천 순서의 근거, 빈자리의 확인 시점, 개인 조건에 따라 달라지는 월비용의 계산 근거를 목록에서 바로 검증하기는 어렵다. 일부 정보는 기관이 직접 확인해야 하는 현재 상태인데 공개 행정자료와 시각적으로 구분되지 않는다.

### 관찰한 시각 시스템

- 흰 배경과 옅은 회색 구분선 중심, 그림자는 매우 약함
- 약 1,200px 안팎의 중앙 콘텐츠와 고정 폭 필터 열
- 둥근 사진, 베이지 계열 특징 태그, 주황색 주요 CTA
- 한 결과를 사진 / 판단정보 / 비용·행동의 세 영역으로 구성

수치는 화면 캡처에 기반한 근사치이며 케어닥의 공식 디자인 토큰이 아니다.

## 2. 돌봄한눈의 경쟁 우위

돌봄한눈은 전국 공공데이터를 기반으로 지도 생활권 탐색, 기관 비교함, 평가 근거, 조건별 공식 수가 계산을 한 흐름에서 제공할 수 있다. 경쟁 방향은 “추천처럼 보이는 카드”가 아니라 다음 네 가지를 검증 가능하게 만드는 것이다.

1. 공개 근거: 공단·심평원 출처와 자료 기준일
2. 판단 요약: 평가등급·평가연도, 등록 정원, 확인된 인력
3. 현재성 구분: 공개자료로 확인된 사실과 기관 문의가 필요한 빈자리·근무·재고·입원 가능 상태
4. 개인화 비용: 고정 월비용 대신 장기요양등급, 본인부담 유형, 이용량, 확인된 비급여를 입력하는 공식 수가 계산

## 3. 적용한 목록 정보 구조

PC 신규 방문자는 목록형을 기본으로 사용한다. 기존에 카드형·간단형을 선택한 사용자의 세션 선호는 그대로 유지하며 모바일은 카드형으로 시작한다.

가로형 한 행의 구조는 다음과 같다.

- 왼쪽: 공단 공개 사진
- 가운데 상단: 순번, 기관명, 주소
- 가운데 판단 영역: 유형별 공단 평가, 등록 정원, 확인된 인력 또는 심평원 개설일
- 가운데 근거 영역: 서비스 유형, 데이터 제공기관, 자료 기준일, 기관 확인 필요 항목
- 오른쪽 행동 영역: 담기·담은 기관 보기, 전화, 상세·비용, 지도 표시

요양원·주야간보호·방문요양의 `상세·비용`은 기존 공식 수가 계산기로 이어진다. 지원하지 않는 유형에는 비용을 약속하지 않고 `상세정보`로 표시한다.

## 4. 데이터 표현 안전 기준

- 등록 정원을 빈자리 수로 표현하지 않는다.
- 공개자료에 없는 대기자·현재 이용 가능 여부·재고·입원 가능 여부를 추정하지 않는다.
- 평가 미확인을 낮은 평가로 취급하지 않는다.
- 서로 다른 평가연도를 같은 순위처럼 비교하지 않는다.
- 인력 누락을 0명으로 바꾸거나 “충분”으로 평가하지 않는다.
- 지정일을 설립연도나 운영경력으로 바꾸지 않는다.
- 사진을 현재 모습이라고 단정하지 않는다.
- 개인 등급·감경·이용량 없이 고정 월비용을 제시하지 않는다.

## 5. 반응형·접근성 기준

- PC 1,001px 이상에서만 가로 비교형을 신규 기본값으로 사용한다.
- 모바일은 기존 카드 흐름과 44px 이상의 조작 영역을 유지한다.
- 보기 전환은 기관 DOM, 광고, 초점, 검색·지도 상태를 재생성하지 않는다.
- 출처와 확인 필요 상태는 색상만이 아니라 텍스트 레이블로도 구분한다.
- 긴 기관명·주소와 글자 확대에서도 가운데 정보 영역이 줄바꿈되도록 한다.

## 6. 실제 데이터로 검증한 서비스 적합성

2026-11-18 배포 자료를 `data/care/*.json.gz`, 공단·사진 매니페스트와 직접 대조했다. 유형 간 중복을 포함한 검색 행은 48,173개이며, 기관기호 기준 공단 장기요양기관 31,033곳과 심평원 요양병원 1,301곳을 구분해 제공한다.

| 유형 | 검색 행 | 평가 연결 | 평가 연결률 | 사진 연결 | 사진 연결률 | 비교 시 주의점 |
|---|---:|---:|---:|---:|---:|---|
| 요양원·공동생활가정 | 6,573 | 5,240 | 79.7% | 6,410 | 97.5% | 2021·2025년 평가가 함께 존재 |
| 주·야간보호 | 5,885 | 3,355 | 57.0% | 5,677 | 96.5% | 2023·2024년 평가가 함께 존재 |
| 방문요양 | 19,276 | 9,730 | 50.5% | 17,130 | 88.9% | 미평가를 낮은 점수로 처리하면 절반 가까이가 왜곡됨 |
| 방문간호 | 1,015 | 292 | 28.8% | 911 | 89.8% | 등록 인력과 실제 배정 가능 인력을 분리해야 함 |
| 방문목욕 | 11,407 | 1,477 | 12.9% | 10,407 | 91.2% | 평가 미확인이 다수이므로 점수 중심 추천에 부적합 |
| 단기보호 | 110 | 29 | 26.4% | 98 | 89.1% | 현재 자리·대기는 기관 확인 필요 |
| 복지용구 | 2,183 | 1,056 | 48.4% | 1,790 | 82.0% | 현재 재고·대여 가능 여부는 공개자료에 없음 |
| 치매전담형 | 423 | 342 | 80.9% | 418 | 98.8% | 기본 유형과 중복되는 모아보기이며 2023~2025년 평가가 섞임 |
| 요양병원 | 1,301 | 해당 없음 | 해당 없음 | 공단 사진 대상 아님 | 해당 없음 | 심평원 개설현황에 공단 장기요양 평가를 적용하면 안 됨 |

공단 평가 원본은 21,216건이고 화면 유형에 연결된 평가 행은 중복 유형을 포함해 21,521개다. 공단 8개 유형의 사진 연결은 42,841/46,872행으로 91.4%다. 따라서 사진을 활용한 빠른 탐색은 데이터 적합성이 높지만, 서로 다른 평가연도와 평가 미확인을 섞은 단순 점수순 추천은 데이터 적합성이 낮다.

이 수치로 다음 결론을 검증했다.

1. 사진·주소·공개 평가 근거를 목록에서 함께 제공하는 것은 실제 자료 충족률이 높다.
2. 빈자리·실제 근무조·방문 배정·재고·입원 가능 여부는 공공데이터로 확정할 수 없으므로 `기관 확인 필요`로 분리해야 한다.
3. 등급·총점 순위는 같은 평가연도가 확인된 2곳 이상에서만 허용해야 한다.
4. 요양병원은 심평원 출처와 개설현황만 사용하고 공단 평가 열을 제공하지 않아야 한다.

## 7. 구현 완료 상태

- 상세 상단에 `확인된 강점 / 기관 확인 필요 / 미확인`을 유형별로 분리했다.
- 비교함에 출처·자료 기준일·평가연도를 표시하고 혼합연도에서는 등급·총점 정렬을 차단했다.
- 비교 엑셀의 첫 시트에 같은 비교 근거와 순위 가능 여부를 기록했다.
- 1,280px 이상이면서 높이 701px 이상인 검색 목록에서는 기존 필터 DOM을 왼쪽 레일로 재사용한다. 작은 화면·담은 기관·지도 화면은 기존 동작을 유지한다.
- 신규 PC는 행형 목록, 모바일은 카드형 목록을 기본으로 하며 사용자가 고른 보기는 세션에서 유지한다.
- `scripts/care-compare-evidence-data.test.mjs`가 배포 압축자료 전체의 개수·출처·실제 혼합연도·동일연도 정렬 정책을 검증한다.

## 8. 남은 확장 범위

1. 사진 등록일을 촬영일로 오인하지 않도록 촬영·수정 시점이 기관에서 확인된 경우만 별도 표시한다.
2. 비용 계산 결과의 포함·미포함 비급여와 기관 확인 질문을 비교함으로 연결한다.
3. 기관 직접 제공 정보는 공단·심평원 자료를 덮어쓰지 않고 확인일·제공 주체와 함께 별도 영역으로만 확장한다.
