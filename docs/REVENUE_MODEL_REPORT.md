# 돌봄한눈 B2B 수익모델 적용·피드백 보고서

작성일: 2026-09-17

## 결론과 현재 성과

**B2B 소개자료 제작을 주 상품으로, 직접 광고를 추가 상품으로 구현했다. 실제 유료 고객·입금·광고 수익 증가는 아직 확인하지 못했다.** 기능 배포를 수익화 성공으로 판정하지 않는다. 월 방문자, 현재 AdFit 수익, 유료 전환율 자료는 제공받지 못했으므로 예상 매출을 실적처럼 표시하지 않는다.

보호자가 무료로 이용하는 기관 검색·비교·공단 정보는 유지한다. 지금 B2C 유료 장벽을 두면 검증되지 않은 지불 의사에 기대면서 기존 검색 유입을 손상시킬 수 있다. 대신 사업자가 납품물을 확인하고 구매할 수 있는 B2B 서비스를 먼저 시험한다. 이는 현재 코드와 미확인 트래픽을 고려한 판단이며 시장 수요가 입증되었다는 뜻은 아니다.

## 판매 모델

| 상품 | 초기 제안가·총 결제금액 기준 | 실제 제공물 | 한계 |
|---|---:|---|---|
| 기관 소개 페이지 제작 | 110,000원 / 1회 | 제공받은 자료로 제작한 반응형 HTML 1개, 서비스 최대 8개·지역·시간·연락처, 문구 수정 1회 | 도메인·상시 유지보수·게시 대행·원고/촬영·유입 보장 제외 |
| 30일 홍보 카드 | 55,000원 / 30일 | 예상 비용과 서비스 소개 하단 동일 광고주 1개, 문구 정리·링크 설정·수정 1회·게재 확인 | 특정 지역 노출·지도 검색 노출·노출량·상담/입소 보장 제외 |

제안가는 시장조사로 검증된 적정가가 아니라 첫 계약을 검증할 실험 가격이다. 세금 처리, 계약 주체, 최종 금액, 납기, 취소·중단 조건은 실제 계약 전에 서면 확정한다. 온라인 결제·자동 연장은 없다. 광고주 한 곳만 노출하는 현재 구조에서 광고 매출 상한은 **30일당 55,000원**이다. 큰 반복 매출이 생기는 구조라고 과장하면 안 된다.

제작 상품은 사이트 방문자가 적어도 납품 가치가 있지만, 고객 획득과 자료 수령·검수는 별도로 필요하다. HTML 파일만으로 공개 링크가 생기지 않으므로 고객 홈페이지 게시 또는 별도 게시 대행을 합의해야 한다.

## 변경한 소스와 고객 동선

1. `advertise.html`·`advertise.css`: 제작 상품, 광고 상품, 제안가, 실제 지면, 제외 범위, 견적 문의를 제공한다.
2. `partner-profile-sample.html`: 가상 업체임을 명시한 제작 견본. 실제 기관이나 실적을 사칭하지 않는다.
3. `scripts/build-partner-profile.mjs`: 광고주가 승인한 입력 JSON으로 독립 HTML 납품물을 생성한다. 미승인·위험 링크·입력 누락을 거부하고 문자열을 이스케이프한다. 기존 결과 파일을 덮어쓰지 않는다.
4. `partner-inquiry.js`·CSS: 상품과 예산을 수신 메일에 포함한다. 두 지도·홈·유형 안내·예상 비용의 기존 문의창을 공용으로 유지한다.
5. 홈·서비스 소개와 기존 공용 문의창에서 상품 안내로 연결한다. 실제 광고 지면은 예상 비용·서비스 소개이며 기존 AdFit 지면은 유지한다.
6. `sponsor-config.js`·`sponsor-card.js`·CSS: 승인된 단일 광고만 계약 기간 안에 표시한다. 미계약 기본값은 `null`이다. 열린 페이지는 1분 주기 및 화면 복귀 시 재검사한다.
7. 기본 검사: 계약 경계·미승인 광고·잘못된 주소·소개자료 입력 삽입 검사를 추가했다.

동선: 기존 사이트의 사업자 안내 → 상품·견본 확인 → 상품이 선택된 문의 → 운영자 견적 → 서면 합의·결제 확인 → 납품 또는 광고 게재.

## 현실적인 손익 기준

매출은 이익이 아니다. 아래는 **세금·결제수수료·영업비용을 차감하기 전의 가정 계산**이다.

- 제작 1건 110,000원, 작업 2시간, 내부 시간비용을 시간당 30,000원으로 가정하면 잔여액은 50,000원이다.
- 작업이 4시간이면 시간비용 120,000원으로 판매금액을 넘는다. 자료 미정리·무제한 수정·게시 작업을 기본 상품에 넣으면 손실 가능성이 높다.
- 제작 5건 + 광고 한 자리 판매 시 총 청구액은 605,000원이다. 이는 판매 목표의 산식이며 매출 예측이 아니다.
- 반복 매출은 광고 갱신에서만 발생한다. 제작을 월 구독으로 표시하거나 한 지면을 여러 광고주에게 독점 판매하지 않는다.

첫 3건은 자료 확인·문구 정리·검수·수정에 쓴 시간을 기록한다. 제작 시간이 2시간을 지속적으로 넘으면 범위를 줄이거나 가격을 다시 시험한다.

## 첫 유료 고객 검증

첫 목표는 **선결제된 제작 1건을 납품하고 수락받는 것**이다. 문의 수나 코드 배포만으로 목표 달성으로 처리하지 않는다.

1. 판매 주체·세금 처리·결제 수단·납기·취소 조건을 확정한다. 결제 계정이 없는 상태에서 임의 계좌나 결제 버튼을 만들지 않는다.
2. 기존 관계가 있거나 제안 수신에 동의한 사업자에게 견본과 상품을 제안한다. 이번 작업에서는 외부 사업자에게 연락하거나 메일을 발송하지 않았다.
3. 고객별 단계는 `동의된 접촉 → 유효 문의 → 견적 → 실제 입금 → 납품 → 수정 → 수락`으로 기록한다. 고객 정보와 입금 자료는 공개 Git 저장소에 저장하지 않는다.
4. 10개 적합 사업자에게 실제 제안을 전달했는데 유효 문의가 0건이면 문구보다 먼저 고객군·필요성을 재확인한다. 자동 발송이나 대량 수집을 늘리지 않는다.
5. 문의는 있는데 5개 견적에서 입금이 0건이면 거절 이유(가격·자료 필요성·파일 활용·신뢰)를 구분해 상품을 수정한다. 이는 운영 판단 기준이지 통계적으로 입증된 임계값은 아니다.
6. 첫 3건의 실 작업시간과 잔여액이 확인되기 전에는 유료 트래픽을 구매하지 않는다.

> 보호자 상담 때 전달하실 기관 소개 자료가 필요하신가요? 제공 서비스·운영시간·지역·연락처를 PC와 모바일에서 읽을 수 있는 한 페이지로 제작합니다. HTML 파일 1개와 문구 수정 1회 기준 제안가는 110,000원이며 게시 대행은 별도 협의합니다. 실제 구성은 https://homecare.designboard.net/partner-profile-sample.html 에서 확인하실 수 있습니다. 필요하시면 자료 범위와 납기를 먼저 확인한 뒤 견적을 안내드리겠습니다.

## 운영 절차

### 소개자료 납품

고객 원본 JSON은 저장소 밖의 비공개 경로에 두고 다음 필드를 사용한다. 개인 휴대폰 대신 공개 승인된 업무 연락처를 사용한다.

```json
{
  "approved": true,
  "name": "광고주가 승인한 업체명",
  "intro": "승인된 소개 문구",
  "region": "실제 서비스 지역",
  "hours": "확인된 운영시간",
  "contact": "공개에 동의한 업무 연락처",
  "url": "https://example.com/",
  "services": ["제공 서비스"]
}
```

```bash
node scripts/build-partner-profile.mjs /비공개경로/승인자료.json /비공개경로/납품본.html
```

`approved: true`는 실제 고객 승인을 받은 뒤에만 넣는다. 예시 JSON을 실 고객 납품에 사용하지 않는다. 생성 후 390px·PC 화면을 확인하고 파일을 납품한다. 공개 게시가 필요하면 고객의 도메인·게시 범위를 별도로 합의한다.

### 광고 게재

결제와 소재 승인을 확인한 뒤 `sponsor-config.js`의 `campaign`에 `id`, `approved: true`, `name`, `title`, `description`, HTTPS `url`, 시간대를 포함한 `startsAt`·`endsAt`을 설정한다. 종료는 배타적이므로 시작부터 정확히 30일 뒤 시각을 사용한다. 계약 기간 중복을 확인하고, 예상 비용·서비스 소개에서 시작/종료 경계와 모바일을 검증한 뒤 배포한다. 갱신은 새 합의 없이는 하지 않는다. 계약 정보·입금액·이메일을 이 공개 설정에 넣지 않는다.

## 확인한 근거와 미완료 조건

- 기존 저장소에 AdFit 광고 ID와 Web3Forms 수신 설정은 연결되어 있었다. 이는 실제 수익·메일 수신 완료를 증명하지 않는다.
- Web3Forms는 추가 폼 필드 수신을 지원한다: [공식 설치 안내](https://docs.web3forms.com/getting-started/installation).
- AdFit은 광고 게재로 수익을 제공하지만 실제 수익 규모는 계정 보고서로 확인해야 한다: [공식 안내](https://adfit.kakao.com/info).
- 현재 중앙 방문·구매 분석과 결제 시스템은 연결되어 있지 않다. 실제 보고서가 없는 상태에서 노출·클릭 리포트 제공을 약속하지 않는다.
- 단순한 B2C 유료 비교 보고서는 무료 기관 정보와의 차별성이 입증되지 않았다. 향후 보호자에게 실제 지불 의사가 확인되고 납품·환불 체계가 마련된 경우에만 별도로 시험한다.
- 이번 결과는 **B2B 상품·견본·접수·납품 도구·광고 운영 기능 적용**이다. 실제 입금과 고객 수락까지는 미완료다.

홈은 `index-map-entry.js`로 통합 지도에 즉시 이동하므로 유료 광고 판매 지면에서 제외했다. 첫 설계의 홈 광고 가정을 실제 브라우저 확인 뒤 수정했다.

## 검증 기록

- 변경 전 `npm run check` 통과.
- `npm run build`로 자료·지역 페이지·사이트맵을 생성했다. 기관 데이터와 815개 지역 페이지는 불필요하게 변경되지 않았다.
- 변경 후 `npm run check` 전체 통과: 두 주야간보호 기관 집합 차이 0, 지역 SEO 815페이지, 공단 목록·상세·사진 31,033곳 검증.
- 신규 자동 검사 4개 통과: 광고 승인·기간 경계·위험 링크, 제작물 입력 이스케이프·미승인 차단.
- 실제 브라우저에서 판매 페이지 PC 1440px·모바일 390px과 견본의 가로 넘침 여부를 확인했다.
- Web3Forms 응답을 로컬에서 모의하여 실패 시 입력·문의창 유지, 성공 시 닫기·완료 토스트, 상품·진입 위치 전달을 확인했다. 실제 메일은 발송하지 않았으며 실제 수신 여부는 검증하지 않았다.
- 서비스 소개에서 임시 메모리 설정으로 활성 광고 표시·스크립트 문자열 이스케이프·만료 숨김을 확인했다. 공개 설정에는 시험 광고를 저장하지 않았다.
- 예상 비용에서 기존 광고 영역 유지와 미계약 슬롯 숨김을 확인했다.
- 두 지도의 네이버 SDK 로딩·지도 DOM 생성과 공용 문의창 연결을 확인했다. 이번 브라우저 검사에서 지도 필터·비교·사진의 모든 동작을 새로 전수 검사한 것은 아니다.

광고 계약 설정을 바꿀 때에는 두 지면의 `sponsor-config.js` 버전도 함께 올리고 공개 반영을 확인한다.
